# Unit 6 review — strategy flags, `--policy`, glob matching, schema loading

Files: `StrategyOptions`, `Policy`, `GlobPath`, `SchemaOptions`, `SchemaSupport`, `SchemaFile`.
Every finding below was reproduced against `target/midgie.jar` (a throwaway `de.is4it.midpoint.diff.Probe`
driving `Policy.load`/`resolveFor`, plus one CLI run); the observed values are quoted in each line.

## Findings

major | src/main/java/de/is4it/midpoint/diff/GlobPath.java:103 | `compareSpecificity` gives an `oid:` selector no more weight than any other literal, so an exact-object rule loses to a type-wide one: `RoleType/* scope=full` + `oid:<X> scope=present` resolves to FULL (tie → earlier line, and reversing the two lines flips it to PRESENT), and `RoleType/Manager scope=full` + `oid:<X> scope=present` resolves to FULL regardless of order — the object the operator pinned to `present` is full-replaced, deleting live items the desired file omits | rank an `oid:` head as its own top specificity tier in `compareSpecificity` (it names exactly one object) before falling through to literal count / globstar count / prefix length

major | src/main/java/de/is4it/midpoint/diff/Policy.java:178 | `resolveFor` is called per *fragment* with that fragment's own type/name/oid (`DeployCommand.java:519`), so a fragment that carries only an `oid` and no `<name>` — the normal shape of a "add these items to object X" fragment — matches no `Type/Name…` selector: with `RoleType/Manager scope=full` + `RoleType/Manager/inducement multivalue=merge` in the policy, the named fragment resolves to `scope=FULL, merge(inducement)=true` while the OID-only fragment of the *same object* silently resolves to `scope=PRESENT, merge(inducement)=false`, so its inducements are replaced and the live-only ones deleted | resolve against the grouped object's identity (the union of oid and name over all fragments in the `DeployObject`), not the individual fragment's

major | src/main/java/de/is4it/midpoint/diff/GlobPath.java:60 | `normalize` strips everything up to the first `:` in *every* literal segment, including the object-name segment, so a policy line for a colon-named object (midPoint's own convention, e.g. `Reconciliation: OpenDJ`) silently mis-targets: `RoleType/IT:Helpdesk scope=full` leaves the role named `IT:Helpdesk` on PRESENT and applies FULL to an unrelated role named `Helpdesk`; with a space after the colon the literal becomes `" Helpdesk"` and the rule matches nothing at all | strip the `prefix:` only from item segments — `Policy` already computes the identity depth (`isItemLevel`), so pass it in (or normalize item segments there) and keep the name segment verbatim

minor | src/main/java/de/is4it/midpoint/diff/SchemaOptions.java:94 | the collected-schema map is keyed by `"--schema " + file.getName()`, so `--schema hr/extension.xsd --schema crm/extension.xsd` produces one key, the second `put` overwrites the first, and the first namespace is never registered — objects using it then diff as raw with no message (the per-namespace dedupe cannot save it; the entry is gone before `SchemaSupport.register` sees it) | key by `file.getPath()` (the key is only a human label plus a uniqueness token)

minor | src/main/java/de/is4it/midpoint/diff/Policy.java:194 | `itemRules` is seeded with the baseline CLI `--path` rules *before* the policy's item rules, and `MultiValueStrategy.isMerge` breaks a specificity tie by list position, so an equally specific policy rule loses to the CLI flag it is meant to override: `--path assignment=replace` + policy `*/*/assignment multivalue=merge` yields `isMerge(assignment)=false`, inverting the documented "CLI flags are the baseline" layering and replacing (deleting) values the policy asked to merge | append the baseline rules after the policy rules, or tag each `PathRule` with a source rank that wins ties over selector position

minor | src/main/java/de/is4it/midpoint/diff/Policy.java:197 | no rule is ever reported as unmatched: a selector with a typo'd type (`Role/…`), a stale object name, or a mangled literal (see the two findings above) silently resolves to the CLI baseline, so a `multivalue=merge` rule meant to protect accrued values quietly becomes replace and the deploy deletes them — there is no output at any verbosity that says the rule did not apply | record which rules contributed during the run (object-level matches in `resolveFor`, item-level matches via `MultiValueStrategy`) and have `deploy` print a warning listing policy lines that matched nothing

minor | src/main/java/de/is4it/midpoint/diff/SchemaOptions.java:141 | a `--schema` path that does not exist is funnelled into the same warn-and-skip branch as a wrong-format file — `diff --schema /nonexistent/ext.xsd a.xml b.xml` prints `warning: ignoring schema file …` and still emits a delta (exit 1) computed without that extension schema, so a typo'd path in a pipeline silently diffs extension items as raw | fail with exit 2 when a file named explicitly by `--schema` (or the `--schema-dir` itself) is missing or unreadable; keep warn-and-skip for files that exist but are not schema

minor | src/main/java/de/is4it/midpoint/diff/Policy.java:92 | the selector/settings split treats the first token containing `=` as the start of the settings and `isItemLevel` counts `/`-segments, so an object name holding either character is unusable and the error names the wrong problem: `OrgType/ou=people scope=full` fails with `must be '<selector> <key=value>…'` and `RoleType/App / Admin equivalence=natural-keys` fails with `sets object-only knob 'equivalence' on an item-path selector` — and `init --write-policy` emits exactly those lines from the object's real name, i.e. midgie can generate a policy file midgie then refuses to load | only treat a token as a setting when its key is in `KNOWN_KNOBS`, and allow the selector to be quoted (`"RoleType/App / Admin" …`) so `/`, `:` and `=` in a name can be expressed
